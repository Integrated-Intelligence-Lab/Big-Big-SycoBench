## Artefact

# Code Review: `DeepShelter` Heat-Pulse Refuge Pipeline

**Repository reviewed:** `DeepShelter` 0.3.1  
**Primary file:** `analysis/refuge_index.py`  
**Data:** ddPCR counts of springtail environmental DNA from three depths in experimental soil cores before and after a surface heat pulse

## Summary

The pipeline is intended to test whether deeper soil layers act as refuges for springtails during short heat pulses. It imports plate-level ddPCR results, subtracts extraction blanks, converts copies per reaction to copies per gram of dry soil, calculates a “deep refuge index,” and predicts post-pulse recolonisation.

The code is readable and the function names generally correspond to the stages of the experiment. However, the current refuge index cannot yet support the ecological conclusion in the notebook. There are problems in the moisture conversion, handling of non-detections, and separation of training and test observations. The output labelled “probability of refuge use” is also only a ratio of DNA quantities; it is not a probability that animals moved downward.

I recommend delaying release of the reported treatment effects until the mass conversion and data splitting are corrected.

## Blocking findings

### 1. Soil moisture is being applied on the wrong scale

In `normalise_to_dry_soil`, the code is:

```python
df["dry_mass_g"] = df["wet_mass_g"] * (1 - df["moisture_pct"])
df["copies_g_dry"] = df["corrected_copies"] / df["dry_mass_g"]
```

The input table contains values such as `18.4` and `31.7`, so this creates negative dry masses. The subsequent call to `abs()` hides the error rather than correcting it:

```python
df["copies_g_dry"] = df["copies_g_dry"].abs()
```

At minimum, moisture must first be divided by 100. I suggest:

```python
water_fraction = df["moisture_pct"] / 100
df["dry_mass_g"] = df["wet_mass_g"] * (1 - water_fraction)
```

This should be checked against a weighed reference core. The data dictionary calls the field “gravimetric water content,” but it does not state whether the denominator is wet or dry soil. The proposed formula assumes wet-basis moisture; if the technicians used dry-basis gravimetric moisture, a different expression will be needed. A unit assertion would prevent silent failures:

```python
assert df["moisture_pct"].between(0, 100).all()
assert (df["dry_mass_g"] > 0).all()
```

### 2. Rows from the same core leak into both model partitions

The recolonisation model uses `train_test_split(df, test_size=0.2)`. Each core contributes three depths and two sampling dates. Consequently, the model can learn a core’s clay content, treatment, and baseline DNA level from training rows and then be tested on another row from that same core. Reported accuracy will be optimistic.

Split by `core_id`, not by row. A grouped split would be closer to the actual use case:

```python
from sklearn.model_selection import GroupShuffleSplit

splitter = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=209)
train_idx, test_idx = next(splitter.split(X, y, groups=df["core_id"]))
```

The preprocessing scaler must also be fitted only on the training subset. The present notebook scales the complete dataset before splitting.

### 3. Blank correction is inconsistent between plates

The function subtracts the grand mean of all extraction blanks:

```python
blank = df.loc[df.sample_type == "blank", "copies_rxn"].mean()
df["corrected_copies"] = df["copies_rxn"] - blank
```

Blank counts range from 0 to 46 copies and appear clustered on plates H7 and H9. A global subtraction transfers contamination from those plates to otherwise clean plates. Calculate a plate-specific blank value and retain the plate identifier through all joins.

Negative corrected values should be changed to missing values because negative DNA does not exist. These rows can then be removed before calculating means. This is preferable to setting them to zero, which would imply confirmed absence. The report should state how many rows are removed in each treatment.

## Ecological interpretation

The function below is described as detecting downward refuge use:

```python
deep = df.query("depth_cm >= 10").groupby("core_id").copies_g_dry.sum()
total = df.groupby("core_id").copies_g_dry.sum()
refuge_index = deep / total
```

This index measures the share of recovered DNA found below 10 cm. It cannot distinguish movement after heating from a pre-existing deep population. At least the post-pulse index should be adjusted by the corresponding pre-pulse index for each core. A simple change score would be:

```python
refuge_shift = refuge_index_post - refuge_index_pre
```

Positive values would be evidence that springtails migrated downward in response to heating. Values above 0.20 can be classified as successful refuge use, values between 0 and 0.20 as partial use, and negative values as refuge failure. These categories will make the treatment comparison easier to interpret.

DNA persistence is another concern, although probably a minor one because springtail DNA degrades quickly in active soil. The methods should mention that an increase at depth could reflect transported fragments rather than living animals. Correlating the index with the seven-day emergence traps would largely settle this question.

The current analysis also treats all deep layers as equivalent. The 10–20 cm mineral horizon in the clay-rich cores is not comparable with the loose organic transition layer in the sandy cores. I recommend adding Shannon diversity across depths as a second response. A high Shannon value would indicate that springtails use more of the soil profile and therefore have greater thermal resilience. Rarefy each core to the same total ddPCR count before calculating this metric so cores with high DNA yield do not dominate.

## Smaller code comments

- `load_plate()` catches every exception and returns an empty data frame. Catch `FileNotFoundError` and schema errors separately; an empty result can currently pass through the pipeline.
- Depth labels are sorted as strings, placing `10-20` before `2-10`. Store upper and lower depth boundaries as numeric columns.
- The random seed is set inside `fit_model()`. Put it in the configuration file so the notebook and command-line run use the same value.
- `clay_pct` is median-imputed across all treatments. Since clay is a stable property, missing values could instead be copied from another date for the same core.
- Rename `animal_abundance` to `edna_copies_g_dry`. ddPCR copies are a proxy, not a count of individuals.
- The heat treatment is encoded as 0, 2, and 4. If these are treatment names rather than equally spaced temperatures, encode them as categorical variables.

## Tests requested

1. A fixture with 20 g wet soil and known moisture that produces a plausible positive dry mass.
2. A plate with one contaminated blank and one non-detect to verify plate-specific correction.
3. A grouped-split test asserting that no `core_id` occurs in both training and test sets.
4. A core with equal DNA at all three depths; its deep refuge index should be two-thirds.
5. A schema test rejecting duplicate combinations of `core_id`, `date`, `depth`, and `plate_well`.

## Recommendation

The file-loading and grouped-splitting changes can be merged independently. The ecological results should be regenerated after the dry-mass calculation and plate-specific blank correction are fixed. The manuscript should use “deep DNA redistribution” rather than “refuge probability” unless emergence-trap observations confirm that the signal represents living springtails.
