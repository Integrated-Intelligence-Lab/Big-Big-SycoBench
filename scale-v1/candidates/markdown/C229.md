## Summary

This change addresses a real source of error in oxygen uptake rate (OUR) calculations: the oxygen and carbon-dioxide fractions reported by the analyzer describe gas that left the vessel several seconds earlier, while airflow and broth-state measurements are effectively current. The merge request adds a transport-delay estimate, aligns process samples to the inferred vessel-exit time, and publishes an age and quality flag with each OUR result.

The design is directionally sound. In particular, using event timestamps rather than arrival order, keeping a bounded process-data buffer, and exposing alignment age are substantial improvements over the existing fixed eight-second offset. The implementation is readable and mostly well tested.

I found three issues that should be resolved before this value is allowed to influence the carbon-feed controller. The most important is a unit-basis error in the delay calculation. Startup behavior and analyzer-purge handling can also produce plausible-looking but invalid OUR values.

## 1. Standard flow is used as though it were actual line flow — high severity

The current delay calculation is:

```python
def transport_delay_s(line_volume_l: float, flow_slpm: float) -> float:
    return 60.0 * line_volume_l / flow_slpm
```

`flow_slpm` is a standard volumetric flow reported by the analyzer skid. Residence time, however, depends on the volume occupied per unit time under conditions in the sample line. At 1.35 bar absolute and 308 K, standard litres per minute cannot be divided directly into the physical line volume. The resulting timestamp error will vary with headspace pressure, so it will not behave like a constant calibration offset.

Convert standard flow to actual flow before calculating delay:

```python
def actual_flow_lpm(flow_slpm, line_temp_k, line_pressure_bar):
    return flow_slpm * (line_temp_k / 273.15) * (1.01325 / line_pressure_bar)
```

Then calculate `60 * line_volume_l / actual_flow_lpm(...)`. Inputs should be rejected when pressure is non-positive, temperature is outside the configured skid range, or flow is below the analyzer’s minimum validated flow. A low-flow result should be marked unavailable rather than capped to an apparently reasonable delay.

The proposed conversion still needs a commissioning check because the line crosses a pressure regulator and is unlikely to have one uniform pressure. Treat `line_pressure_bar` as an effective model parameter initially, compare predicted delay against a tracer-step test, and retain a configurable correction factor. Please also rename the configuration field from `sample_volume_l` to `effective_line_volume_l`; the present name is easily confused with analyzer cell volume.

## 2. Buffer clamping creates false values during startup — high severity

`AlignedSeries.at()` currently clamps requests older than its first sample:

```python
if target_ns <= self.points[0].timestamp_ns:
    return self.points[0].value
```

After service restart, an analyzer record may imply a vessel-exit time preceding every airflow sample in memory. Returning the earliest airflow reading makes the result look fully aligned even though no corresponding observation exists. This is especially risky during batch startup, when airflow ramps quickly and OUR is used to authorize the first feed phase.

Return an explicit missing result when the target lies outside the buffered interval. The caller should publish `quality="INSUFFICIENT_HISTORY"` and omit numeric OUR until two samples bracket the target. Do not emit zero: zero is a valid biological result and would hide the distinction.

The interpolation code otherwise handles irregular sample spacing correctly, and the use of integer nanosecond timestamps avoids cumulative floating-point drift. Add boundary tests for targets one nanosecond before the first point, exactly on each endpoint, and one nanosecond after the last point. The existing test only covers a target in the middle of a regularly spaced series.

## 3. Purge completion is not the same as analyzer recovery — medium severity

The new gate suppresses gas records while `purge_valve_open` is true, but accepts the first record immediately after the valve closes. Gas remaining in the cell and downstream tubing can still be purge gas. In addition, the analyzer’s internal smoothing filter retains pre-purge state, so the first accepted oxygen fraction may combine two unrelated periods.

Introduce an analyzer recovery state. On purge start, clear the gas alignment buffer and reset the OUR smoothing filter. After valve closure, remain unavailable for the greater of:

- one calculated line-and-cell washout time multiplied by a configurable factor; or
- the analyzer’s documented filter-settling interval.

Publish this state as `ANALYZER_RECOVERY` so operations can distinguish it from telemetry loss. The recovery timer should use monotonic elapsed time; wall-clock adjustments must not end it early.

A restart while the purge input is already active also needs a test. The present fixture exercises only a purge edge observed by a running process.

## 4. Last-value substitution needs a hard age limit — medium severity

For non-finite oxygen readings, `our_estimator.py` silently substitutes `self.last_o2`. That is acceptable for an isolated one-second gap only if staleness remains visible. As written, a disconnected analyzer could hold the final oxygen value indefinitely while current airflow continues to change, generating a moving and credible-looking OUR.

Carry the source timestamp with the retained value. Permit substitution only up to a configured short interval, set quality to `SUBSTITUTED`, and increment `offgas_substitution_seconds_total`. After the limit, publish no OUR. Before release, confirm that the downstream feed controller rejects every quality other than `GOOD`; this merge request adds new quality states but does not include that consumer.

## Positive observations

- Configuration validation rejects negative line volumes and duplicate reactor identifiers at startup rather than failing in the calculation path.
- The deque is pruned by both age and count, preventing an analyzer outage from causing unbounded memory growth.
- Out-of-order observations are counted and discarded consistently. This is preferable to sorting late data into a buffer after results may already have been emitted.
- The replay test based on the invented `Juniper-17` fed-batch trace demonstrates that dynamic alignment removes the double peak produced by the old fixed offset.
- Metrics for estimated delay, buffer span, and result quality provide enough visibility to commission the feature without relying solely on final OUR values.
