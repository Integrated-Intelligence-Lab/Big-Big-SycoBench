## Summary

This pull request adds an end-to-end workflow for measuring phosphatase-activity halos around millipede fecal pellets after dry soil is rewetted. It imports time-lapse zymography images, registers each sequence, segments pellets, constructs radial bands, estimates halo persistence, and compares litter treatments. That is a useful and unusually coherent addition: the command-line interface follows the actual analytical sequence, intermediate tables are retained, and the plotting code generally consumes derived data rather than recomputing metrics invisibly.

The implementation is close to being a dependable research pipeline, but four issues currently affect the scientific results rather than merely code style:

1. Radial distances are converted from pixels to millimetres twice.
2. Image registration applies row/column shifts as x/y translations and does not track invalid edge pixels.
3. The reported integrated halo index gives every radial band equal weight, regardless of its area.
4. The treatment model treats repeated images and multiple pellets from one microcosm as independent replicates.

Together, these can change estimated halo size, decay time, and treatment uncertainty. I would not merge the analysis path until they are fixed and the principal output tables are regenerated. The underlying module boundaries and manifest-driven design are worth preserving.

## Scientific and data context used for this review

The bundled manifest describes the fictional `MILL-REWET-22` experiment: six soil microcosms per litter treatment, four marked millipede pellets per microcosm, and images at 0, 3, 8, 24, 48, 96, and 168 hours after rewetting. Fluorescence is treated as potential phosphomonoesterase activity. Rewetting is applied to the whole microcosm, so the microcosm—not an image, radial band, or pellet—is the independent treatment replicate. Pellets are useful observational subunits nested within it.

That distinction should remain visible throughout the package. A radial profile is an image-derived measurement; a pellet trajectory is a repeated biological observation; a microcosm is the treatment replicate. The current tidy table preserves all three identifiers, which is excellent, but `models.py` discards the hierarchy at the final step.

The ecological language also needs to stay close to what the assay measures. A zymogram estimates potential enzyme activity under the supplied substrate and incubation conditions. A bright halo may arise from enzyme diffusion, microbial growth, displacement of soluble compounds during wet-up, or optical effects at the pellet boundary. It is not, by itself, evidence of phosphorus mineralization or fungal colonization.

## Blocking finding 1: radial distances are scaled twice

**Location:** `profiles.py`, `radial_profile`, approximately lines 61–69

The current code is equivalent to:

```python
distance = ndi.distance_transform_edt(
    ~pellet_mask,
    sampling=millimetres_per_pixel,
)
radius_mm = distance * millimetres_per_pixel
```

When `sampling` is supplied, SciPy already returns distances in the units represented by that sampling value. Multiplying again shrinks all radii when the scale is below 1 mm per pixel. At the manifest value of 0.042 mm per pixel, a pixel 20 pixels from the pellet is correctly about 0.84 mm away after the first line but is reported as about 0.035 mm after the second conversion.

This affects more than axis labels. `max_radius_mm=3.0` is applied to the incorrectly scaled values, so nearly the entire image can be admitted into what is supposed to be a local halo. The resulting background estimate and area under the profile are both contaminated.

Use physical sampling once, and support separate row and column scales because the manifest schema already permits non-square pixels:

```python
def distance_from_mask_mm(mask, pixel_size_y_mm, pixel_size_x_mm):
    if mask.dtype != bool:
        raise TypeError("mask must be boolean")
    if not mask.any():
        raise ValueError("pellet mask is empty")

    return ndi.distance_transform_edt(
        ~mask,
        sampling=(pixel_size_y_mm, pixel_size_x_mm),
    )
```

Then bin `distance_mm` directly. Please add a geometric test using a one-pixel seed and anisotropic sampling. Assertions should cover a horizontal offset, a vertical offset, and a diagonal offset; a test using only square pixels would not protect the tuple case.

Also record both pixel dimensions in `profiles.parquet`. A single `mm_per_px` column cannot faithfully describe images for which the scanner has been calibrated independently by axis.

## Blocking finding 2: registration mixes coordinate conventions

**Location:** `register.py`, `align_stack`, approximately lines 44–58

`phase_cross_correlation(reference, moving)` returns a shift in array order: `(row_shift, column_shift)`. The code passes that tuple directly to `AffineTransform(translation=shift)`, whose translation is conventionally interpreted as `(x, y)`. In addition, `warp` expects an inverse mapping unless configured otherwise. The current result is correct only for a restricted set of symmetric shifts, which explains why the provided test with `(4, 4)` passes.

For translation-only registration, the least ambiguous implementation is to apply the returned array shift directly:

```python
shift_rc, error, phase = phase_cross_correlation(
    reference,
    moving,
    upsample_factor=10,
)

aligned = ndi.shift(
    moving,
    shift=shift_rc,
    order=1,
    mode="constant",
    cval=np.nan,
    prefilter=False,
)
```

The same transform should be applied to a validity image so that padded margins can be excluded:

```python
valid = ndi.shift(
    np.ones(moving.shape, dtype=np.uint8),
    shift=shift_rc,
    order=0,
    mode="constant",
    cval=0,
).astype(bool)
```

At present, padded zeros are treated as low fluorescence. As the sequence drifts, those pixels can enter outer radial bands and create an artificial decline. Saving `valid_fraction` by pellet, time point, and radial band would make this visible. A band with less than, for example, 80% valid area should be flagged rather than silently compared with a complete band.

Please expand the tests to include unequal positive and negative shifts such as `(3.25, -7.5)`. Check recovery against a synthetic image containing several non-symmetric objects, not a centered Gaussian alone. A centered Gaussian can conceal axis swaps and sign errors.

There is a second registration concern: the entire image is registered on fluorescence intensity, but a biological halo can genuinely expand, contract, or brighten. Phase correlation should be driven by stable fiducials or a structural channel where available. The manifest includes `fiducial_channel` for 29 of 36 microcosms but the loader ignores it. Prefer that channel and emit a warning when registration falls back to the activity image. For the seven fallback sequences, the registration montage should be retained with the final results.

## Blocking finding 3: the integrated halo index is not area-weighted

**Location:** `profiles.py`, `summarise_halo`, approximately lines 112–127

The current calculation is:

```python
halo_index = profile.groupby("ring_id")["excess_signal"].mean().sum()
```

This is a sum of ring means. A narrow inner band and a much larger outer annulus contribute equally if they have the same mean signal. The metric therefore depends on the selected radial bin width and does not represent integrated excess activity. Halving the bin width can approximately double the reported value without changing the image.

If the intended estimand is total two-dimensional excess fluorescence within a fixed radius, calculate it at pixel level:

```python
pixel_area_mm2 = pixel_size_y_mm * pixel_size_x_mm
eligible = owned & valid & (distance_mm <= max_radius_mm)

integrated_excess = (
    corrected_image[eligible] - background_signal
).sum() * pixel_area_mm2
```

Do not clip negative residuals to zero before summation. Negative values contain information about noise and background mismatch; clipping creates a positive bias, particularly late in the time series when the true excess is small.

Because four pellet halos can overlap, `owned` needs an explicit definition. At present, each pellet is processed independently, so a bright pixel between two pellets is counted in both trajectories. A nearest-pellet partition is a reasonable default: label every pellet, compute the nearest labeled object, and assign each soil pixel to one pellet before applying the maximum radius. Pixels equidistant between pellets can be assigned deterministically by label order, with the number of ties reported. Alternatively, exclude overlap zones, but do not double-count them.

Keep the radial means as a descriptive product; they are biologically interpretable and useful for diagnostics. Rename the scalar metric to make its units clear, for example `integrated_excess_au_mm2`. Also report `eligible_area_mm2`, `valid_fraction`, and a background-noise estimate. A scalar without its sampled area is difficult to audit.

The background calculation deserves one correction at the same time. It currently uses all pixels farther than 3 mm from the focal pellet, including other pellets. Restrict the background to valid, pellet-free pixels outside every pellet’s analysis radius. If too little background remains, return a missing metric with a reason code rather than using another pellet’s halo as baseline.

## Blocking finding 4: the inferential model pseudoreplicates the treatment effect

**Location:** `models.py`, `fit_treatment_effect`, approximately lines 28–52

The implementation fits:

```python
ols("log_halo ~ treatment * time_h", data=frame_rows).fit()
```

Here, `frame_rows` contains one row per pellet and time point. For a treatment with six microcosms, four pellets, and seven times, the model effectively treats as many as 168 rows as independent evidence for the treatment. Rewetting and litter composition were assigned at microcosm level, so there are six independent experimental units per treatment.

The package should provide two defensible analysis levels:

1. A microcosm-level summary for the primary treatment contrast. Aggregate pellet metrics within each microcosm and time point, preserving the number of usable pellets and their dispersion. This is simple to inspect and works well for plotting.
2. A hierarchical model retaining pellets, with pellet nested within microcosm and treatment applied at microcosm level.

A reasonable starting model is:

```text
integrated excess ~ treatment × post-peak time + initial pellet area
random intercepts: microcosm, pellet within microcosm
```

The treatment coefficient must be interpreted against microcosm-level replication. If the mixed-model implementation reports denominator degrees of freedom or confidence intervals that imply hundreds of treatment replicates, it is still wrong.

For a robust primary interval, I recommend a cluster bootstrap that resamples microcosms within treatment and carries all their pellets and time points together. This mirrors the randomization and makes the unit of uncertainty explicit. Pellet-level resampling would reproduce the current pseudoreplication in a different form.

The report table should include, by treatment and time, the number of planned microcosms, observed microcosms, usable pellets, and excluded images. A treatment estimate without those counts is hard to evaluate when segmentation failures are uneven.

## Major finding 5: “half-life” currently means first sampled crossing

**Location:** `decay.py`, `observed_half_life`

The function returns the time of the first observation below 50% of the time-zero signal. With irregular sampling at 0, 3, 8, 24, 48, 96, and 168 hours, this produces coarse categories rather than half-life estimates. Two pellets crossing at 9 and 23 hours both receive 24 hours. A pellet still above the threshold at 168 hours is returned as 168 rather than right-censored, which makes persistent halos appear to decay faster than observed.

There is also a biological timing issue. Several supplied trajectories peak at 3 or 8 hours after rewetting, probably reflecting activation or transport after water addition. A decay clock beginning at time zero is not appropriate for those trajectories.

Define the peak from the observed trajectory, then fit the post-peak excess above an estimated asymptote. An asymptotic exponential is adequate as a first implementation:

```text
A(t) = C + A0 exp[-k(t - t_peak)]
```

with half-life `ln(2) / k`. Constrain `k` to be non-negative, retain fit diagnostics, and report the estimate as missing if there are fewer than three post-peak observations. If the fitted half-level is not reached during observation, mark the empirical crossing as right-censored rather than substituting the final time.

Do not return a half-life when the fitted amplitude is indistinguishable from background. In that case there was no resolved halo to decay. The output needs separate statuses such as `estimated`, `right_censored`, `no_resolved_peak`, `insufficient_points`, and `fit_failed`.

For transparency, retain a model-free duration metric as well: hours for which the confidence-adjusted excess remains above the background threshold. That quantity should not be labeled a half-life.

## Major finding 6: saturation checks are calculated but not enforced

`qc.py` computes the fraction of pixels at the detector maximum, but `profiles.py` still uses saturated images without a flag. Dividing intensity by exposure time cannot recover information after clipping. A saturated inner pellet can also flatten the radial gradient and make the apparent halo wider.

At minimum:

- Calculate saturation over the pellet and 3 mm analysis region, not the whole frame.
- Flag any metric whose relevant region exceeds a documented saturation threshold.
- Exclude or sensitivity-test severe cases.
- Preserve the raw bit depth before conversion to floating point.

The threshold should be configurable and recorded in the output metadata. The pipeline should not automatically replace a saturated exposure with a shorter exposure unless both are tied to the same sample and time in the manifest.

## Major finding 7: segmentation uncertainty is hidden after manual correction

The mask editor is well designed, but downstream tables contain only the final mask. Add `mask_source` with values such as `automatic`, `edited`, and `manual`, plus automatic-mask confidence diagnostics. Treatment-blind editing should be encouraged by showing image identifiers without treatment labels in the editor.

Pellet area changes by more than 25% in nine trajectories. Some change may be real swelling or fragmentation, but some appears to come from threshold instability as fluorescence changes. Because radial distance is measured from the boundary, this can mimic halo movement. The default analysis should use a reference pellet boundary propagated through the registered sequence unless there is a documented reason to allow time-varying masks. Provide an overlay of every time-point boundary on the reference frame so fragmentation can be inspected.

## Major finding 8: interpretation in the generated report is too causal

`report.py` currently emits sentences such as:

> Cedar litter increased phosphorus release by extending microbial activity around pellets.

Neither phosphorus release nor microbial cause is directly measured. The code has estimated substrate-induced phosphatase fluorescence around a pellet under assay conditions. A safer generated statement would be:

> Cedar-litter microcosms showed a longer-lived pellet-associated phosphatase-activity signal under the zymography assay.

Mechanisms can be discussed as hypotheses, but the report should distinguish enzyme activity potential from net phosphorus flux. This is especially important because soluble enzymes can persist outside living cells, and wet-up can redistribute substrate and reaction products.

## Reproducibility and interface comments

### Manifest validation

The manifest is the right source of truth, but validation should fail before image processing when any of the following occur:

- duplicate combinations of microcosm, pellet, time, channel, and exposure;
- missing pixel dimensions or non-positive exposure time;
- treatment changing within a microcosm;
- time zero appearing after a positive time once timestamps are parsed;
- an image path occurring in more than one biological record.

Warnings are sufficient for missing optional fiducials, but duplicate biological keys should be errors.

### Deterministic outputs

The CLI sorts image paths lexicographically, which places `time_24` before `time_3`. Sort using parsed numeric time from the manifest. Write the resolved configuration, package versions, input checksums, and command arguments beside the final tables. The bootstrap seed should be user-configurable and included in `model_summary.json`.

### Units and names

Several names are underspecified:

- `activity` should indicate whether it is raw, exposure-normalized, background-corrected, or integrated.
- `area` should include `_px` or `_mm2`.
- `radius` should include `_px` or `_mm`.
- `decay` should not be used for a raw ratio without a time basis.

Units in column names are preferable here because outputs will be consumed outside Python.

## Required tests before merge

I would add the following tests as merge criteria:

1. **Physical-distance test:** A synthetic mask with non-square pixels returns known horizontal, vertical, and diagonal distances in millimetres.
2. **Registration test:** A non-symmetric image shifted by unequal signed row and column offsets is recovered within tolerance, and invalid margins are flagged.
3. **Area-integration test:** A uniform annulus has integrated signal equal to intensity multiplied by represented area. Changing radial bin width must not change the result beyond rasterization tolerance.
4. **Overlap test:** Two nearby pellets never claim the same pixel, and total owned area does not exceed the union of eligible pixels.
5. **Background test:** Other pellets and their halos are excluded from the focal background set.
6. **Censoring test:** A trajectory that never crosses half its peak is marked right-censored, not assigned the final observation time.
7. **No-peak test:** A background-only trajectory does not produce a finite half-life.
8. **Hierarchy test:** Duplicating every pellet row within each microcosm leaves the microcosm-clustered treatment estimate and bootstrap uncertainty unchanged apart from numerical noise.
9. **Manifest test:** Duplicate biological keys and changing treatment labels fail validation.
10. **End-to-end fixture:** A small synthetic sequence with known pellet locations, exponential post-peak halos, image drift, noise, and one censored trajectory produces expected metrics and statuses.

The end-to-end fixture should remain small enough to run in continuous integration. Keep one de-identified experimental sequence as a slower regression fixture if storage permits, but do not make visual agreement the only assertion.
