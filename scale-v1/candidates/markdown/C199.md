## Summary

This merge request adds a useful end-to-end path from repeated cross-shore profiles to event-level sediment-loss estimates. The separation between ingestion, profile comparison, and event aggregation is clean, and the new `ProfileDelta` record makes the resulting measurements easier to audit than the dictionaries returned by the previous prototype. The command-line output is also sensibly explicit about survey identifiers and overlap length.

The main concern is that the implementation currently produces plausible but incorrect results for several ordinary profile shapes. In particular, the erosion-only integration bridges unsampled gaps, timestamps without offsets are interpreted in the wrong timezone, and the uncertainty calculation treats spatially correlated observations as independent. The first two can change the reported erosion volume itself; the third makes the confidence interval misleadingly narrow.

## Blocking findings

### 1. Erosion integration bridges disconnected regions

In `volume.py`, the code removes non-eroding points and then integrates what remains:

```python
mask = dz_m < -min_change_m
loss_m2 = -np.trapezoid(dz_m[mask], station_m[mask])
```

This creates artificial sediment loss when eroding points are separated by a stable, accreting, or missing section. For example, if erosion is detected at stations 5–10 m and 55–60 m, `trapezoid` draws a continuous edge across the intervening 45 m after the mask has removed those samples. The result depends on the distance between patches rather than only on the measured eroding area.

Keep the full station sequence and integrate contiguous runs independently. Missing-data gaps should also break a run, even when the valid samples on either side both indicate erosion.

```python
def integrate_loss(station_m, dz_m, min_change_m, max_gap_m):
    active = np.isfinite(dz_m) & (dz_m < -min_change_m)
    breaks = (~active) | np.r_[True, np.diff(station_m) > max_gap_m]
    group = np.cumsum(breaks)

    total = 0.0
    for key in np.unique(group[active]):
        idx = active & (group == key)
        if idx.sum() >= 2:
            total += -np.trapezoid(dz_m[idx], station_m[idx])
    return total
```

The exact grouping implementation can differ, but the behavior should be covered by a test with two erosion patches separated by accretion and another with a survey gap. `max_gap_m` should be part of the site configuration rather than inferred from the largest spacing in each profile.

### 2. Naive survey timestamps are being treated as UTC

`read_surveys()` currently uses:

```python
df["observed_at"] = pd.to_datetime(df["observed_at"], utc=True)
```

For strings without an explicit offset, this assigns UTC rather than converting from the logger’s local civil time. The subsequent nearest-tide join can therefore select the wrong tidal window, especially around daylight-saving transitions. Because the event filter rejects surveys more than three hours from predicted low water, the error can also cause valid surveys to disappear silently.

Require either offset-bearing timestamps or an explicit `source_timezone` in the import configuration. Localize first, handling ambiguous and nonexistent civil times deliberately, and only then convert to UTC:

```python
parsed = pd.to_datetime(raw, errors="raise")
if parsed.dt.tz is None:
    if source_timezone is None:
        raise ValueError("Naive survey times require source_timezone")
    parsed = parsed.dt.tz_localize(
        source_timezone,
        ambiguous="raise",
        nonexistent="raise",
    )
df["observed_at"] = parsed.dt.tz_convert("UTC")
```

Please add tests for an offset-bearing timestamp, a naive timestamp with configuration, and an ambiguous clock time. The exported table should retain both normalized UTC and the original source string for traceability.

### 3. Pointwise bootstrap understates uncertainty

`bootstrap_loss()` resamples individual stations with replacement. Adjacent elevation residuals are correlated because the surface is spatially smooth and because instrument alignment errors affect runs of observations together. Treating 400 stations as 400 independent samples can yield a very confident interval even when there are only a few effectively independent profile sections.

Use a moving-block bootstrap over chainage, preserving station order within each block. A 20 m block is a reasonable default for these profiles, with shorter final blocks allowed at the seaward boundary. Also expose the block length in the output metadata so that downstream reports do not present the interval without its modeling assumption.

The random generator is already injected into the function, which is good. Retain that design and add a deterministic test showing that intervals widen when residuals are strongly correlated. If there are too few blocks for resampling, return an explicit “insufficient support” status rather than zero-width bounds.

## High-priority findings

### 4. Duplicate stations can multiply rows during alignment

The merge in `align.py` assumes one elevation per `station_m`, but neither importer enforces that constraint:

```python
paired = old.merge(new, on="station_m", suffixes=("_old", "_new"))
```

Repeated shots at the same rounded station produce a many-to-many merge and overweight that location. Validate uniqueness after station rounding, or define an aggregation rule such as median elevation plus a count. Use `validate="one_to_one"` in the final merge so future import changes fail loudly. Profiles should also be sorted before integration, with strictly increasing chainage checked after deduplication.

### 5. Horizontal units are implicit

The calculations assume that `station_m` and `segment_width_m` are metres, but the CSV schema does not record how stationing was derived. A profile generated from angular coordinates or feet will pass validation and produce a numerically credible result with the wrong units.

Add a unit field to the profile manifest and reject anything other than metres at this layer. If profiles are built from geometries elsewhere in the pipeline, that conversion should verify a projected coordinate system and write the conversion provenance into the manifest. This module should not attempt a silent conversion.

## Tests and maintainability

The existing tests cover identical profiles, uniform lowering, no overlap, and reproducibility with a fixed seed. Those are valuable baseline cases. Please add the following before merge:

- reversed input station order;
- duplicate station values on one and both surveys;
- two erosion patches separated by accretion;
- a gap larger than `max_gap_m`;
- naive local timestamps around a clock change;
- all-change-below-threshold and single-active-point cases;
- correlated synthetic residuals for the block bootstrap;
- an input manifest whose distance unit is not metres.

Consider replacing the current exact floating-point assertions with `pytest.approx` where integration order may vary. Conversely, keep exact assertions for status codes, survey pairing, and random-seed reproducibility.

## Non-blocking notes

- `ProfileDelta.loss_m3` is calculated by multiplying cross-sectional loss by `segment_width_m`. The name is clear, but the documentation should state that this is a representative-cell estimate, not a direct three-dimensional surface difference.
- The warning emitted for less than 40% profile overlap is helpful. Include the actual overlap percentage and shared chainage interval in the structured result, not only in the log message.
- `n_boot=10_000` may be expensive when processing the full archive. A vectorized block-index implementation or a lower configurable default may be worthwhile, but correctness should be resolved before optimization.

Once gap-safe integration, timezone handling, and spatially aware uncertainty are addressed, the architecture should support the proposed event summaries without a broader redesign.
