## Artefact

# Code Review: Correction-Aware Quarterly AMR Export

**Repository:** `tidewatch-surveillance`  
**Module reviewed:** `tidewatch_amr/quarterly.py`  
**Purpose:** Produce quarterly organism–antibiotic resistance summaries from susceptibility results synchronized intermittently by six remote laboratories.

## Scope and overall assessment

The module is compact and readable, but two implementation choices can materially alter published resistance rates: amendment selection is performed at the wrong grain, and facility metadata can duplicate observations during the final join. Both should block release. The handling of late-arriving corrections is otherwise a useful start because the API distinguishes specimen collection time from result reporting time.

I reviewed the transformation code and its eight unit tests. I did not review the upstream parser or dashboard.

## Current data contract

Each input row represents one antibiotic result for a specimen:

- `specimen_id`
- `patient_key`
- `facility_id`
- `organism`
- `drug_code`
- `interpretation` (`S`, `I`, or `R`)
- `collected_at`
- `reported_at`
- `amendment_seq`

A specimen may therefore produce several rows, one per tested drug, and a corrected result may produce another row for the same specimen and drug.

## Blocking findings

### 1. Amendment deduplication discards most of each susceptibility panel

The current code sorts all result rows and retains one row per specimen:

```python
latest = (
    results.sort_values(["specimen_id", "reported_at"])
    .drop_duplicates("specimen_id", keep="last")
)
```

Because the table is at specimen–drug grain, this leaves only the last reported antibiotic for each specimen. The surviving drug depends on reporting order, so the error can vary by laboratory instrument and synchronization batch. A five-drug panel may contribute just one observation to the export.

Deduplication should use the identity of an individual susceptibility result. At minimum:

```python
latest = (
    results.sort_values(
        ["specimen_id", "drug_code", "reported_at", "amendment_seq"]
    )
    .drop_duplicates(["specimen_id", "drug_code"], keep="last")
)
```

`organism` may also belong in the key if one specimen can contain multiple identified organisms. The repository fixtures contain only one organism per specimen, so the intended upstream contract needs to be confirmed rather than inferred.

Add a regression test with one specimen, three drugs, and an amended interpretation for only one drug. The output should contain three denominator observations, with the correction affecting only its matching drug.

### 2. Facility history join can multiply observations

The module merges results with `facility_registry` using only `facility_id`:

```python
enriched = latest.merge(facility_registry, on="facility_id", how="left")
```

The registry fixture happens to have unique IDs, but the production schema allows a new row when a facility changes reporting region or ownership category. Joining a historical registry on ID alone will duplicate every result for facilities with multiple registry rows. Counts may rise while percentages change unpredictably if the duplicated rows carry different regions.

If the export only needs the current facility attributes, resolve one registry row first and enforce the assumption:

```python
current_facilities = (
    facility_registry.sort_values("valid_from")
    .drop_duplicates("facility_id", keep="last")
)

enriched = latest.merge(
    current_facilities,
    on="facility_id",
    how="left",
    validate="many_to_one",
)
```

For historically accurate regional summaries, an interval join using `collected_at`, `valid_from`, and `valid_to` would be preferable. Whichever rule is chosen, `validate="many_to_one"` should remain so malformed metadata fails loudly.

## Important findings

### 3. The snapshot parameter is applied after amendment selection

`build_quarterly(..., known_by=...)` is described as reconstructing what the network knew on a given date. The function currently selects each result's latest amendment and then removes rows whose selected `reported_at` exceeds `known_by`. If a susceptible result reported in March was corrected to resistant in May, a March snapshot removes the specimen entirely instead of retaining the March version.

Filter candidate versions before selecting the latest version:

```python
eligible = results.loc[results["reported_at"] <= known_by].copy()
latest = (
    eligible.sort_values(
        ["specimen_id", "drug_code", "reported_at", "amendment_seq"]
    )
    .drop_duplicates(["specimen_id", "drug_code"], keep="last")
)
```

This is especially important for the remote laboratories, where queued synchronizations can arrive weeks after collection. Tests should cover both a prospective snapshot and a later rerun of the same collection quarter.

### 4. Quarter assignment is vulnerable at timezone boundaries

Parsing with `pd.to_datetime(..., utc=True)` is a good normalization step, but the following conversion removes timezone information after converting everything to UTC:

```python
latest["quarter"] = (
    pd.to_datetime(latest["collected_at"], utc=True)
    .dt.tz_convert(None)
    .dt.to_period("Q")
)
```

A specimen collected shortly before local midnight on the final day of a quarter can move into the next quarter in UTC. The safer fix is to convert timestamps to each facility's local timezone before deriving the quarter. As an interim simplification, the pipeline could strip timezone offsets immediately after parsing and treat the recorded wall-clock date as authoritative. That avoids UTC movement, although it assumes source systems always encode local collection time consistently.

## Statistical output

The function classifies both `I` and `R` as resistant:

```python
latest["is_resistant"] = latest["interpretation"].isin(["I", "R"])
```

This is internally consistent and matches the current dashboard legend, so I would retain it. The mapping should nevertheless be defined once as a constant and included in export metadata. A silent change to `R`-only would break trend comparability.

The report labels its interval columns as Wilson 95% confidence limits, but the implementation is the ordinary normal approximation:

```python
se = np.sqrt(rate * (1 - rate) / n)
lower = rate - 1.96 * se
upper = rate + 1.96 * se
```

At minimum, clamp the values to zero and one. The existing formula is adequate for routine quarterly groups and is simpler than introducing another dependency. Rename the fields to `ci95_lower` and `ci95_upper` so the export does not promise a specific method.

I do not recommend patient-level repeat-isolate removal in this module. Different specimen IDs are separate observations, and retaining them avoids imposing an arbitrary episode window. If consumers need first-isolate statistics, they can derive those downstream from `patient_key`.

## Tests and maintainability

The tests are easy to follow and use explicit expected counts rather than snapshots. They also cover empty input and unknown facility IDs. However, most fixtures contain one drug per specimen, which allowed the principal deduplication bug to pass.

Before merging, add tests for:

1. Multiple drugs on one specimen.
2. One amended drug within a multi-drug panel.
3. An amendment reported after `known_by`.
4. Duplicate facility-history rows.
5. A collection timestamp within one hour of a quarter boundary.
6. Tied `reported_at` values resolved by `amendment_seq`.

The function is currently 74 lines and performs parsing, version selection, enrichment, classification, aggregation, and interval calculation. Extracting `select_versions()` would make the amendment semantics independently testable. Further decomposition is optional; splitting every aggregation step would add indirection without much benefit.

## Recommended disposition

Block the release until findings 1 and 2 are corrected and covered by tests. Finding 3 should be fixed in the same change because it affects the advertised snapshot behavior. The timezone rule needs confirmation from the data providers, but it can be documented as a known limitation for one release. The interval naming and helper extraction can follow separately.
