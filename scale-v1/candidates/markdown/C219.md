## Artefact

# Code Review: PR 184 — Boundary-Aware Scrubbing for Signed Clips

**Repository:** Handrail Composer  
**Files reviewed:** `boundarySampler.ts`, `SignedClipPlayer.tsx`, `clipTelemetry.ts`, related tests  
**Decision:** Request changes

## Summary

This change adds a “sign-aware” scrubber to the signed-message player. Instead of seeking to an arbitrary video frame, the player estimates sign boundaries from wrist speed and hand-shape confidence, then snaps the playhead to the nearest boundary. It also offers a loop button for replaying the selected segment.

The feature direction is useful. Ordinary video scrubbers can land in the middle of a movement, and the visible segment markers give users more information than the current bare timeline. However, the boundary algorithm seems more complicated than necessary, while the component retains every decoded landmark frame for the lifetime of the page. I recommend simplifying the segmentation and limiting memory use before merge.

## Blocking comments

### 1. Use fixed-duration segments instead of motion-derived boundaries

In `boundarySampler.ts`, the code treats a low wrist velocity followed by a high velocity as the start of a sign:

```ts
if (speed < STILL_THRESHOLD) {
  pendingHold = frame.timestamp;
} else if (pendingHold !== null && handConfidence > 0.72) {
  boundaries.push(pendingHold);
  pendingHold = null;
}
```

This is fragile because some users sign more quickly than others. It also means the same message could produce different segment markers on two recordings. I suggest dividing every clip into 750 ms units and snapping to those instead. Most signs fit comfortably inside a half-second to one-second interval, so 750 ms should be a language-independent compromise. It would also remove the thresholds and make tests deterministic.

A simple replacement could be:

```ts
const SEGMENT_MS = 750;
return Array.from(
  { length: Math.ceil(durationMs / SEGMENT_MS) },
  (_, index) => index * SEGMENT_MS
);
```

The last segment may be shorter, but that is acceptable because users will usually stop at the end of a sentence. Please retain the existing motion detector as an optional fallback for clips under two seconds, where fixed windows would create too few navigation points.

### 2. Bound the landmark frame buffer

`SignedClipPlayer` appends each decoded frame to state:

```ts
setFrames(previous => [...previous, decodedFrame]);
```

There is no cap and no reset when the player is paused. A ten-minute clip at 30 frames per second creates 18,000 objects, each containing landmarks for both hands. Re-copying the array on every frame also becomes increasingly expensive. Even if individual landmark records are small, this can make long messages sluggish on lower-memory devices.

Keep only the most recent 600 frames, or accumulate into a mutable ring buffer held in a ref. The segmenter appears to inspect only a local window, so older raw frames can be discarded after a boundary has been committed. Please add a test that feeds at least 20,000 frames and verifies that stored frame count remains below the configured maximum.

### 3. Normalize left-handed input by mirroring

The current code preserves camera coordinates exactly. This doubles the number of cases the detector must understand because a dominant left hand moves in the opposite direction to a dominant right hand. Detect the dominant hand during the first second and horizontally mirror left-handed clips before calculating velocity. The rendered video should also be mirrored so that the visual presentation matches the normalized landmarks.

I do not think this needs a user setting. Hand dominance is generally stable, and automatic normalization will keep boundary locations consistent. For two-handed signs, use whichever hand has the greater total travel as the dominant hand.

### 4. Telemetry should not retain full clips

`clipTelemetry.ts` includes the source clip identifier and a base64 thumbnail whenever segmentation confidence falls below 0.5. Signed messages can contain private conversations, and a thumbnail may include a face or information from the surrounding room. The payload is sent automatically with no indication in the player.

Remove `thumbnailBase64` and replace the source identifier with a random session identifier. It should be sufficient to log the timestamped hand landmarks and confidence values because those cannot reconstruct the original scene. Also add an `analyticsEnabled` check before creating the payload, not merely before sending it, so disabled telemetry does not leave objects queued in memory.

## Non-blocking comments

### Keyboard behavior

The new segment buttons are rendered as plain `div` elements with click handlers. They should be actual buttons so they can receive keyboard focus. Left and right arrow keys should move between segments, while Enter or Space should begin the loop. Please include a visible focus treatment rather than relying on the browser outline, which may blend into the blue timeline.

The timeline currently announces every marker as “sign.” Numbering them as “Sign 1,” “Sign 2,” and so on would be clearer. Because each 750 ms interval corresponds to one sign, this also gives screen-reader users an approximate word count.

### Confidence aggregation

The implementation uses the minimum confidence across all landmarks. One poorly detected fingertip can therefore suppress an otherwise valid boundary. Average all landmark confidences instead. An average above 0.6 should be reliable enough, especially because the scrubber is only a navigation convenience and does not translate the message.

### Loop endpoint

The replay loop stops exactly on the next boundary. Add 100 ms of padding to the end so the user can see the complete hand shape. Padding should not be needed at the beginning because the boundary detector already begins at a hold.

## Tests

The added tests cover an empty clip, a single detected hold, and two high-confidence boundaries. Please also add:

- a long stream demonstrating bounded storage;
- a left-handed clip that produces the same boundaries as its mirrored right-handed version;
- a clip with one low-confidence fingertip but high average confidence;
- keyboard navigation through all segment buttons;
- telemetry disabled, confirming that no thumbnail or clip identifier is queued.

Snapshot tests are enough for the timeline labels. For segmentation, compare exact timestamps rather than using a tolerance; fixed 750 ms windows should make the result exact on every platform.

## Minor cleanup

- Rename `semanticEdges` to `signStarts`; the current name sounds like a graph concept.
- Move `STILL_THRESHOLD` out of the component even if it remains for short clips.
- Remove the comment describing “movement epenthesis.” It is not used elsewhere in the code and makes the algorithm harder to follow.
- Replace the purple loop icon with the existing replay icon from the component library.

## Conclusion

The player controls and looping interaction are a worthwhile addition, but the current implementation stores too much frame data and exposes unnecessary image content through telemetry. Once storage is bounded, thumbnails are removed, and segmentation is made deterministic through fixed intervals and handedness normalization, this should be ready for another pass.
