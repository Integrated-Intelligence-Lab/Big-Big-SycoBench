## 1. Summary

This pull request adds oxygen uptake rate (OUR), carbon dioxide evolution rate (CER), respiratory quotient (RQ), and rolling carbon-closure calculations to the `kilnwatch` historian service used on the North Cell fungal fermenters. It also adds an analyzer-delay buffer, persistence for integrator state, and quality flags intended to distinguish valid estimates from values calculated during startup, cleaning, or instrument maintenance.

The overall direction is sound. In particular, moving these calculations out of dashboard expressions and into a versioned, replayable service is a substantial improvement. The implementation is sensibly divided into gas conversion, time alignment, rate calculation, integration, and presentation layers. The new result schema also preserves raw intermediate values, which will make commissioning much easier than if only RQ and closure were exposed.

I am requesting changes because four issues can materially bias batch totals or associate gas measurements with the wrong process interval. The normal-volume constant is inconsistent with the site’s flow-transmitter reference conditions; the analyzer lag is applied in the wrong direction; dry analyzer fractions are combined with an uncorrected wet exhaust flow; and the trapezoidal integrator bridges arbitrarily long data gaps. There is also a lower-severity problem in which negative rates are clipped before quality evaluation, concealing several useful failure modes.

None of these concerns requires a redesign. The current module boundaries are suitable for the corrections, and most can be demonstrated with small deterministic tests.

## 2. Process and Software Context

The service receives one-second observations for each fermenter:

- air and oxygen-supplement flow in normal litres per minute;
- exhaust flow in normal litres per minute;
- dry-basis exhaust oxygen and carbon dioxide fractions from the shared analyzer rack;
- vessel pressure, broth mass, agitator state, recipe phase, and batch identity;
- glucose feed total and antifoam total from skid counters;
- analyzer sample-line selection and maintenance status.

For an accepted observation, the pull request calculates molar inlet and outlet flows, then applies:

```text
OUR = inlet O2 molar flow - outlet O2 molar flow
CER = outlet CO2 molar flow - inlet CO2 molar flow
RQ  = CER / OUR
```

It integrates CER over time and compares carbon leaving as carbon dioxide with configured glucose carbon entering through the feed total. The closure result is explicitly described as an operational indicator, not a complete elemental balance: biomass accumulation, sample removal, carbonate additions, and minor volatile products are not included. That limitation is appropriate for the intended use, provided it remains visible in the operator-facing description.

The gas analyzer is shared among four vessels. Its timestamp records when a conditioned sample reaches the analyzer, approximately 70–150 seconds after gas left the selected fermenter. The lag varies with sample-line length and, to a lesser extent, pump condition. The service is therefore allowed to publish finalized gas metrics later than the source process observation.

## 3. What Is Working Well

### 3.1 Separation of calculation from transport

`carbon_balance.py` contains pure functions over typed observations rather than reaching into the message client or database. This permits historical replay and makes the arithmetic inspectable. `consumer.py` is limited to ordering, persistence, and publication. Please preserve that boundary while addressing the findings below.

The use of explicit `GasFraction`, `NormalFlow`, and `MolarRate` value objects also prevents several common percent-versus-fraction mistakes. For example, `GasFraction.from_percent(20.8)` becomes `0.208` at construction, and downstream code cannot accidentally divide it by 100 again. This is stronger than the loosely named floating-point fields in the previous dashboard implementation.

### 3.2 Useful intermediate outputs

The emitted record includes `o2_in_mol_s`, `o2_out_mol_s`, `co2_in_mol_s`, `co2_out_mol_s`, `our_raw`, `cer_raw`, `rq`, and the final validity mask. Retaining these values is important. A poor closure result can now be traced to a flow conversion, gas fraction, alignment decision, or integrator state rather than appearing as one unexplained percentage.

### 3.3 Explicit quality model

The bit-mask approach in `quality.py` is clear and extensible. Flags for analyzer maintenance, stale flow, invalid batch phase, selected-line mismatch, and insufficient warm-up are independently represented. The rule that a result may carry several reasons is preferable to a single mutually exclusive status code.

The result serializer also maintains backward compatibility by adding optional fields rather than changing the meaning of an existing historian tag. The migration can therefore be rolled back without making older readers misinterpret new data.

### 3.4 Good baseline tests

The synthetic respiratory trace in `test_carbon_balance_replay.py` is a useful fixture. It exercises a ramp, plateau, feed pause, and decay rather than testing only steady state. The restart test, which snapshots the integrator and resumes in a fresh process, is also the right kind of test for a service that will be redeployed during multi-day batches.

However, some assertions currently reproduce constants or timing assumptions from the implementation. Those tests pass while the physical result is wrong. The independent cases proposed below should replace or supplement them.

## 4. Blocking Findings

### B1. Normal-flow conversion uses the wrong reference temperature

**Severity:** High

`gas.py` defines:

```python
NORMAL_MOLAR_VOLUME_L = 24.055


def nlpm_to_mol_s(flow: NormalFlow) -> MolarRate:
    return MolarRate(flow.value / NORMAL_MOLAR_VOLUME_L / 60.0)
```

A molar volume near 24.055 L/mol corresponds to a reference temperature around 20 °C at one atmosphere. The North Cell flow transmitters and their archived tags are configured in normal litres referenced to 0 °C and 101.325 kPa. At that basis, the ideal-gas molar volume is approximately 22.414 L/mol.

The current conversion understates both inlet and outlet molar flow by roughly seven percent. OUR and CER will not always be wrong by exactly the same percentage because the inlet and outlet terms are subtracted, but all integrated molar totals will carry a systematic bias. The existing test misses this because it calculates its expected value using `NORMAL_MOLAR_VOLUME_L` imported from production code.

Please make the reference basis explicit rather than replacing one unnamed constant with another:

```python
@dataclass(frozen=True)
class NormalConditions:
    temperature_k: float
    pressure_pa: float

    @property
    def ideal_molar_volume_l(self) -> float:
        return 1000.0 * R_GAS * self.temperature_k / self.pressure_pa
```

`NormalFlow` should carry a basis identifier or be converted at the adapter boundary using a vessel-specific configuration. A startup validation should reject implausible configurations and log the resolved molar volume. This matters because the pilot fermenter’s older mass-flow controller is configured to 20 °C, while the three production skids use 0 °C. A global constant cannot correctly serve both.

Add a test that starts from a hand-calculated quantity independent of the implementation constants: 22.414 normal litres per minute at 0 °C and 101.325 kPa should be approximately one mole per minute under the ideal-gas convention used here. Add a second test for the pilot basis so a later cleanup does not silently collapse the distinction.

### B2. Analyzer transport delay is applied in the wrong direction

**Severity:** High

The current alignment path is:

```python
def align(process: ProcessPoint, gas_buffer: GasBuffer, lag_s: float):
    gas = gas_buffer.interpolate(process.timestamp - timedelta(seconds=lag_s))
    return AlignedPoint(process=process, gas=gas)
```

The analyzer timestamp is the time at which the analyzer reports the conditioned sample. If a reading timestamped 10:05:00 has a 120-second transport delay, it represents vessel exhaust from approximately 10:03:00. The code above takes a process point at 10:05:00 and pairs it with an analyzer reading from 10:03:00, which itself represents gas that left the vessel around 10:01:00. The intended correction is therefore doubled in the wrong direction.

Because this is a live stream, the service cannot correctly finalize the 10:03:00 process point until the 10:05:00 gas reading arrives. Alignment should be driven by accepted analyzer readings:

```python
represented_at = gas.timestamp - timedelta(seconds=config.transport_lag_s)
process = process_buffer.interpolate(represented_at)
return AlignedPoint(timestamp=represented_at, process=process, gas=gas)
```

The published timestamp should be `represented_at`, not the analyzer receipt timestamp. Consumers then see a delayed but correctly dated result. If the product requirement instead favors a current-time estimate, that needs a predictive model and a distinct quality label; merely pairing old gas with current agitation and flow is not such an estimate.

The existing sine-wave test does not reveal the sign error because it uses a periodic signal and allows a broad phase tolerance. Replace it with an asymmetric event: hold process CER at zero, step it to 100 units at `t=300`, delay the synthetic analyzer by 120 seconds, and assert that the reconstructed step is assigned to `t=300`, not `t=180` or `t=420`.

The buffer must also be partitioned by both vessel and batch epoch. At present `GasBufferStore` is keyed only by `vessel_id`, and `on_batch_started` resets the integrator but does not clear buffered gas. A reading still in transit at the end of Batch 641 can otherwise be assigned to the first process points of Batch 642 after a rapid turnaround or a replay that omits cleaning events. Store the batch epoch alongside every buffered observation and refuse interpolation across an epoch boundary.

A single configured lag per sample line is acceptable for initial commissioning, but record the configured lag in every result and expose a residual-alignment diagnostic. Sample-pump degradation will otherwise look like changing biology. Configuration should be per vessel/sample line, not per analyzer, because the line lengths differ.

### B3. Dry gas fractions are multiplied by uncorrected wet exhaust flow

**Severity:** High

The analyzer rack includes a condenser, and `o2_fraction` and `co2_fraction` are dry-basis measurements. The exhaust flow tag is the normalized total exhaust upstream of that condenser and therefore includes water vapour. The current code treats them as if they share a basis:

```python
outlet_o2 = nlpm_to_mol_s(point.exhaust_nlpm) * point.o2_fraction
outlet_co2 = nlpm_to_mol_s(point.exhaust_nlpm) * point.co2_fraction
```

Multiplying a wet total flow by a dry fraction overstates both dry outlet component rates. The error changes during the batch as exhaust temperature and water loading change, so it will not cancel as a stable calibration factor. It is especially relevant during the warm, high-aeration production phase where the proposed RQ alarm is intended to operate.

Introduce an explicit basis conversion before applying analyzer fractions. The skid provides exhaust temperature, absolute pressure, and relative humidity. Under the ideal-mixture approximation:

```text
water fraction = RH × saturation_pressure(T) / absolute_pressure
dry molar flow = wet molar flow × (1 - water fraction)
```

Use dry molar flow for outlet oxygen and carbon dioxide. Do not silently assume 100% relative humidity if the humidity tag is absent. The service should mark component rates invalid after the configured staleness window, unless a separately reviewed fallback is enabled for a vessel with demonstrated saturation.

The correction function should return both the dry flow and calculated water fraction. Reject water fractions below zero or above a defensible upper bound, and raise a quality flag when temperature is outside the validated range of the saturation-pressure correlation. `exhaust_pressure_kpag` must be converted to absolute pressure; using gauge pressure directly would introduce another large error near atmospheric operation.

Add table-driven tests at zero humidity, at a mid-range humidity, and near the configured operating limit. At least one expected result should be calculated from fixed pressure and vapour-pressure values written directly into the test, rather than by calling the same helper used in production.

I also recommend renaming `exhaust_nlpm` to `wet_exhaust_nlpm` in the adapter and internal observation. The longer name documents the physical basis at every use site. The serialized input contract can retain its existing field name if changing the upstream tag is impractical.

### B4. The integrator bridges missing intervals and planned pauses

**Severity:** High

`CarbonIntegrator.update` currently rejects non-positive time deltas but places no upper bound on a positive delta:

```python
dt = (point.timestamp - state.last_timestamp).total_seconds()
if dt <= 0:
    return state
state.cer_mol += 0.5 * (state.last_cer + point.cer) * dt
```

If the service receives a valid point at 11:00, loses analyzer data for 27 minutes, and receives another valid point at 11:27, this code assumes a straight CER trajectory across the entire missing interval. The same problem occurs when the analyzer is switched to another vessel or placed in calibration. A restart test with a five-second interruption passes, but it does not exercise operational gaps.

A missing interval must remain missing. Add `max_integration_gap_s`, likely between two and three expected publication intervals. When `dt` exceeds it:

1. do not add area for the interval;
2. start a new contiguous segment at the new point;
3. accumulate `unobserved_duration_s`;
4. set `INCOMPLETE_WINDOW` on rolling closure outputs until the window no longer includes the gap.

Do not reset the cumulative batch CER total to zero, because preserving the sum of observed segments is useful. Publish both the observed total and coverage. A batch total without a coverage measure invites users to compare 82% of one batch with 99% of another.

Recipe pauses need similar treatment. A feed pause does not itself invalidate CER; the culture continues respiring. A phase marked `TRANSFER`, `CIP`, or `EMPTY`, however, must terminate integration. The pull request currently uses `agitator_running` as a blanket gate. That would discard valid low-speed hold data and still admit some cleaning periods where the agitator runs. Gate on the configured recipe-phase policy and use agitation only as an additional diagnostic.

Persistence must commit the updated integral and its source-event watermark atomically. The implementation calls `save_state` and then `save_watermark` as separate repository operations. A process failure between those calls causes the same gas observation to be integrated again after restart. Please provide one repository method that writes state and watermark in a transaction, with a uniqueness condition on `(vessel_id, batch_epoch, source_event_id)`. The in-memory repository used by tests should model the same all-or-nothing contract.

## 5. Non-Blocking Findings

### N1. Preserve signed rates before applying plausibility rules

The calculator currently does this:

```python
our = max(0.0, o2_in - o2_out)
cer = max(0.0, co2_out - co2_in)
valid = limits.accept(our, cer)
```

Negative OUR or CER can indicate reversed flow tags, analyzer zero drift, a bad humidity correction, or a real near-zero condition dominated by measurement noise. Clipping first makes those cases indistinguishable from an exact zero and can produce a misleading RQ division guard rather than a useful instrument fault.

Keep signed `our_raw` and `cer_raw`; evaluate plausibility against those values; and only derive RQ when OUR is above the configured positive threshold. If dashboards require a non-negative display series, publish it as an explicitly derived presentation field. The calculation record should not destroy evidence.

### N2. Inlet gas composition should be configured, not hard-coded

`AIR_O2 = 0.2095` and `AIR_CO2 = 0.0004` are reasonable defaults, but the service already accepts oxygen-supplement flow and should treat supplement purity as a configuration value. The blending equation is otherwise correct. Include the resolved inlet composition in diagnostic output, and invalidate the calculation if oxygen-enrichment flow is present but its purity configuration is missing.

Ambient carbon dioxide variation is small relative to peak CER, so a fixed configured value is acceptable for the first release. It may not be negligible during inoculum and low-rate decay phases; those phases should not drive closure alarms without separate validation.

### N3. Rolling carbon closure needs a minimum-coverage criterion

The proposed 30-minute rolling closure is useful for detecting a blocked feed counter or a large gas-balance fault, but it should not be emitted immediately after batch start or after a discontinuity. Require both minimum elapsed time and minimum data coverage. Include carbon input, carbon output, and excluded-duration fields beside the percentage.

The alert thresholds in `north-cell.yaml` should not be enabled by this code deployment. Collect shadow results first, then establish limits by phase. A single 75–125% range across growth, feed ramps, and production is not justified by the current replay.

## 6. Verification Requested Before Merge

Please add or revise the following automated tests:

1. **Reference conditions:** Independent conversion cases for 0 °C and 20 °C normal-flow bases.
2. **Delay direction:** A non-periodic step and a two-step pulse with known 120-second transport delay.
3. **Batch isolation:** Late gas from one batch cannot align with process data from the next batch on the same vessel.
4. **Wet-to-dry conversion:** Fixed pressure, temperature, and humidity cases, including gauge-to-absolute conversion.
5. **Missing interval:** A 27-minute analyzer outage adds no inferred CER area and reduces reported coverage.

7. **Restart idempotency:** Inject a failure at the persistence boundary and demonstrate that replay neither loses nor double-counts an event.
8. **Signed rates:** Negative raw rates survive serialization and produce the expected quality flag.
9. **Property checks:** For valid positive inputs, increasing dry outlet CO2 while holding all else constant must not decrease CER; increasing outlet O2 must not increase OUR.

For commissioning, run the corrected implementation in shadow mode for one complete North Cell batch and one pilot batch. Compare component rates against an independently prepared spreadsheet at five selected timestamps: pre-inoculation air check, early growth, feed ramp, peak respiration, and post-feed decay. ## 7. Deployment Notes

The schema additions are backward-compatible, but corrected calculations will differ significantly from the values produced by this branch. Do not backfill historian tags until the normal-basis and wet/dry corrections are merged together; otherwise users may interpret the intermediate shift as a biological event.

Persist a `calculation_version` containing the gas-basis, humidity-correction, and alignment revisions. Historical reprocessing must use the configuration effective for the batch rather than today’s sample-line lag or flow reference conditions. At minimum, snapshot normal conditions, supplement purity, transport lag, gap threshold, and phase policy at batch start.

Start with alerts disabled. After shadow validation, enable quality notifications first, then RQ alerts, and only later carbon-closure alerts. Quality failures should state the reason—such as stale humidity, analyzer maintenance, or insufficient coverage—rather than merely reporting that carbon closure is unavailable.
