## Artefact

# Code Review: PR 184 — Left-Handed Playback in VelaSign

**Decision:** Request changes

## Summary

This patch adds a `dominantHand` preference and mirrors avatar poses for left-handed playback. The settings control is straightforward, and persisting the choice in `LocalPrefs` is sensible. Most of the renderer work can be much simpler, however.

## Blocking: cached pose mutation

In `PoseMirror.ts`, the callback passed to `frames.map()` changes `joint.x` directly. Those joints belong to the sequence stored in `PhraseCache`, so replaying the same phrase can mirror an already-mirrored pose. That may make the avatar alternate handedness between plays.

Clone the sequence before transformation:

```ts
const copy = JSON.parse(JSON.stringify(frames));
return mirror(copy);
```

Please add a test that plays one cached phrase three times and compares every result with the first playback.

## Simplify the mirror operation

There is no need for `dominantJointIds` or the special handling of shoulder rotation. Mirror the entire skeleton by negating every x-coordinate. Sign content is carried by hand location and movement, so facial controls and torso lean can remain unchanged. A geometric reflection preserves the meaning automatically, including asymmetric two-handed signs.

This also means the cache key does not need the handedness value: store one pose sequence and reflect it at render time. The JSON clone should be inexpensive enough for 60 fps because phrases contain only a few hundred numbers.

## Tests

The wrist-position snapshot is sufficient coverage for correctness. I would remove the proposed review session with sign-language users; deterministic coordinate transforms are better verified in unit tests, and subjective feedback could delay the release. Add only one case for an empty frame list.

## Nit

Rename `isSinistral` to `leftHanded`. The current term is uncommon and makes the settings code harder to scan.
